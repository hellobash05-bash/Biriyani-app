# Firebase + Supabase Integration Guide

This guide explains how to set up the integration where Firebase handles Authentication and Supabase handles Data Storage.

## 1. Database Setup (Supabase SQL Editor)
Paste and run this SQL in your Supabase SQL Editor to create the necessary tables for tracking user history and data.

```sql
-- 1. Create Activities table (for history)
CREATE TABLE IF NOT EXISTS activities (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  firebase_uid TEXT NOT NULL,
  activity TEXT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Create Projects table (for saved work)
CREATE TABLE IF NOT EXISTS projects (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  firebase_uid TEXT NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  data JSONB,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Enable RLS (Optional but recommended for security)
ALTER TABLE activities ENABLE ROW LEVEL SECURITY;
ALTER TABLE projects ENABLE ROW LEVEL SECURITY;

-- 4. Create simple policies (Allow all for development)
-- In production, you should restrict this to: firebase_uid = auth.uid()
CREATE POLICY "Allow all for activities" ON activities FOR ALL USING (true);
CREATE POLICY "Allow all for projects" ON projects FOR ALL USING (true);
```

## 2. Environment Configuration

### Backend (.env)
Ensure your backend knows how to connect to your Supabase project.
```env
PORT=5000
SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_ANON_KEY=your-public-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-secret-service-role-key
```

### Frontend (.env.local)
Ensure your frontend can communicate with both Firebase and your Local/Hosted Backend.
```env
# API URL (Point to your backend)
NEXT_PUBLIC_API_URL=http://localhost:5000/api

# Firebase Config
NEXT_PUBLIC_FIREBASE_API_KEY=your-api-key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your-auth-domain
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your-storage-bucket
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your-sender-id
NEXT_PUBLIC_FIREBASE_APP_ID=your-app-id
```

## 3. How it Works (Logic Overview)

### A. The User Sync (`AuthContext.tsx`)
When a user logs in via Google (Firebase), the `onAuthStateChanged` listener triggers.
It sends the Firebase User object to the Backend `/api/users/sync` endpoint.

### B. Database Upsert (`backend/index.js`)
The backend takes the Firebase `uid` and performs an `upsert` in the `users` table. 
- If the user is new, it creates a profile.
- If the user exists, it updates the `last_login` timestamp.

### C. Persistent Data Retrieval (`profile/page.tsx`)
Whenever the user visits their profile, the app fetches data from `activities` and `projects` tables using their `firebase_uid`. Because the UID is permanent, the data stays visible forever across different devices.

## 4. Testing the Flow
1. **Login:** Use Google Login.
2. **Log Activity:** On the Profile page, click the "Log Activity" button.
3. **Verify in Supabase:** Go to the Supabase Dashboard -> Table Editor -> `activities`. You should see a new row with your Firebase UID.
4. **Persistence:** Logout and log back in. Your "Recent Activities" will still be visible.
